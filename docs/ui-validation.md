## 確認した問題と修正

- **タブレットのPLAY重なり**：768×1024でクマの操作矩形下端814.7pxに対しPLAY上端809.0pxとなり約6px重なった。1024×768でも左右に重なり、縦横比1.1の直前にも発生。縦向き/横幅の狭い構図とPLAY幅を調整。関連サイズを再検証し、操作矩形の分離、入口可視性、クマの全体表示、近クリップ面への非接触を確認した。
- **タッチ操作が消える条件**：従来CSSは幅700px以下だけ表示。幅1180px以下またはcoarse pointerへ表示対象を拡張。プレイ中の表示は既存の操作モード制御を維持。CSS上の修正であり、実際のタッチ機器では未確認。
- **映像と骨格の比率**：videoはcontain、骨格は固定400×300。16:9/縦長映像と一致しないため、実映像比率のCanvasへ変更。4:3、16:9、9:16、3:4、4:3への切替と未検出時の消去を自動確認。カメラ映像の目視は未実施。
- **背後のゲーム再開**：一時停止中の遊び方/動きの確認にEscapeが伝わる経路を遮断。タッチ入力もモーダル中は受け付けず、背景をinertにする。閉じた後の入力復帰を自動確認。
- **小さい操作/長いパネル**：44px最低操作寸法、長いID/金額/エラーの折返し、共有パネルのスクロール、スキャンの大きいプレビューと縦横配置、HUD/下部操作のsafe-areaを修正。CSSの実レイアウトは未確認。
- **ソフトキーボード**：VisualViewportでモーダルの高さ/位置を調整し、フォーカス欄をスクロール領域へ維持する。表示領域844→324px・上端42px→復帰、API非対応時の代替、解除を模擬テスト。実ソフトキーボードでは未確認。

- **safe-areaの反映**：CSSで取得する左右/下の余白をリサイズ時にロビー配置へ渡す。左右44px/下21px、縦画面の下34pxを模擬し、PLAY/クマの分離と回転時の更新を確認。実ノッチの測定ではない。縦横比1.1の境界はCSSとJavaScriptで同じ「以下」に揃えた。

- **高さ540/550pxの旧指定**：コース案内だけが境界で非表示/再表示となる旧CSSを整理し、低い横画面の500px条件へ統一。境界前後を検証対象へ追加した。
