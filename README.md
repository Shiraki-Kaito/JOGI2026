# 積分アニメーション — Cairo版一式

二重積分・累次積分のStreamlitアプリです。アニメーション本体を同梱しています。
関数、分割数、初期カメラ角度、拡大率、画質を設定し、MP4の生成・再生・ダウンロードができます。

## 起動
ZIPを展開し、app.pyがあるフォルダーで、普段Manimを使っているPython環境を有効にします。

```powershell
python -m pip install -r requirements.txt
python -m streamlit run app.py
```

Windowsでは上記の依存パッケージ導入後、start_windows.batでも起動できます。
Python環境に加え、LaTeXとdvisvgmが必要です。既に動画を生成できていた環境を使用してください。
Manim Communityは0.19.0を使用します。OpenGLは使用しません。

## 操作
1. 二重積分または累次積分を選ぶ。
2. 関数、分割数、角度、画質を設定する。
3. 「動画を作成」を押す。
4. 完成後、動画を確認して「MP4をダウンロード」を押す。

最初の比較は、これまでと同じ関数・二重積分・8×6・360pで行ってください。
生成後は「処理時間の詳細」「詳細ログ」を開けます。ログもダウンロードできます。
設定を変更した際、表示中の動画が前回のものならその旨を表示します。

## 数式
例：`2.0 - 0.4*x**2 - 0.35*y**2`、`1 + 0.4*cos(x)*cos(y)`、`1.5`。
変数はxとy。掛け算は`*`、累乗は`**`または`^`。
`sin`, `cos`, `tan`, `exp`, `log`, `sqrt`, `abs`, `pi`, `e`に対応します。
領域は−2≦x≦2、−1.5≦y≦1.5。許容する高さは−1〜2.5です。
負の高さは元の動画と同じく0付近に切り上げます。符号付き積分の可視化には対応していません。
動画の数式ラベルは元の演出と同じf(x,y)です。

## 今回の変更
- 二重積分のカメラ周回中、入力が一致する面の陰影計算を再利用します。
- 柱数、曲面の分割数、色、透明度、演出時間、カメラ軌道は変更していません。
- 成功・失敗のどちらでもログを保持します。
- 例外のログを検出した場合、監視周期約0.1秒で終了処理を開始します。
  OSによる子プロセス終了には別途時間がかかる場合があります。
- エラーと実際の30分の制限時間超過を区別します。

## 確認範囲と限界
Pythonの構文と陰影計算の出力一致を確認しています。
この一式のStreamlit画面は今回の環境では起動確認できていません。
描画プロセス監視の成功・異常終了・例外後に停止しないケース・時間切れをLinux上で確認しています。
Windowsのプロセス終了処理と、実動画のCairo描画・見た目・生成速度は未確認です。
このZIPは起動用ファイルを揃えた一式です。1分以内の生成を達成した版ではありません。
同じ設定で見た目と生成時間を比較してください。

ローカル利用向けです。利用者のPCにManimとLaTeX環境が必要です。

# Bear Ski

MediaPipeで全身を認識し、クマと一緒に雪山を滑るWebゲーム。後ろから追うカメラ、急斜面、ローポリ9：リアル1の自然な雪景色を目指す。初期のクマは服なし。購入したマフラーだけ任意で着用できる。

## ルール

- 固定距離2,000mを滑り切るタイムアタック。通常速度17m/sなら約118秒、タック加速は最高31m/s。衝突で減速する。
- 左右移動、ジャンプ、しゃがみ＋前傾による加速。
- 昼 → 夕方 → オーロラの夜へ、コース進行に合わせて変化。
- HUDに経過タイム、ベストタイム、残り距離、獲得コイン、スコア、速度を表示。
- ゴールするとタイム・ベストタイム・スコア・コイン・ジャンプ回数を表示。
- ベストは短い完走タイム。カメラ／キーボード共通、2,000mコースの個人記録。
- カウントダウンと一時停止は記録に含めない。物理更新は最大1/60秒に分割し、描画速度による距離の差を抑える。2秒以上の処理遅延時は一時停止。

## 操作

| 動作 | カメラ | キーボード |
|---|---|---|
| ターン | 正面を向いて左右に重心移動 | ← → / A D |
| ジャンプ | その場でジャンプ | Space / ↑ |
| 加速 | しゃがみ＋前傾を保つ | ↓ / S |
| 一時停止 | 画面のボタン | Esc |

カメラを許可し、頭から足先まで映してまっすぐ3秒立つと、自動で基準姿勢を合わせる。その後3秒のカウントダウンで開始。姿勢を1.5秒見失うと自動で姿勢合わせへ戻り、3秒静止＋カウントダウン後に同じ滑走を再開する。距離・タイム・コイン・スコアは保持し、姿勢合わせ中は進まない。タブを離れた場合と手動の一時停止は、再開ボタンを使う。映像はブラウザー内で処理し、サーバーへ送信しない。タッチ操作も用意。

## コインとショップ

- コース上のコイン1枚で残高+1。ゴール時にまとめてアカウントへ保存する。
- 途中でタイトルへ戻る／リロードする場合、その滑走は保存しない。
- 赤、青、黄、緑、紫のマフラーを各25コインで購入できる。購入するとその色を着用。
- 購入済みマフラーの着替えと「マフラーなし」は無料。
- 保存中は再プレイ／タイトルへ移動できない。失敗時は結果を保持し、再試行ボタンを表示する。保存完了前にページを閉じると未保存記録は失われる。

## アカウント保存

Sitesのログイン済みユーザーIDをサーバーで取得し、D1に残高、所有色、着用色、ベストタイムを保存する。同じアカウントなら別端末でも引き継げる。既存の非公開アクセス設定を維持する。

クライアントが渡すユーザーIDは使用しない。すべてのSQLをユーザーIDで絞り込み、書き込みは同一オリジンからのJSONリクエストのみ受け付ける。完走記録はユーザーID＋滑走IDで一意に管理し、記録追加・残高加算・ベスト更新・加算済みフラグ更新を1つのトランザクションで処理する。再試行しても二重加算されない。購入は残高・未購入条件付きの単一UPDATEで処理する。

これは個人向けのハッカソンMVP。時間／コインはクライアントの完走報告を範囲チェックして保存し、サーバー側で滑走全体を再現する不正対策やランキングは対象外。

## 技術

- Three.js 0.170.0 / Vite 6.1.0
- MediaPipe Tasks Vision 0.10.18 + Pose Landmarker Lite（モデルとWASM同梱）
- Worker ESM + D1、Drizzleによるスキーマ管理
- フロント: `web/game.js`, `web/account.js`, `web/auto-calibration.js`
- API: `worker/index.js`、スキーマ: `db/schema.ts`
- WebGL非対応時はCanvas描画へ切り替える。

## 開発と公開

```sh
npm install
npm test
npm run db:generate # スキーマ変更時だけ実行
npm run build
```

出力は`dist/client`の静的アセットと`dist/server/index.js`のWorker。Workerには`DB`（D1）、`ASSETS`（静的アセット）をバインドする。`dist/.openai`にホスティング設定と生成済みマイグレーションを含め、Sitesで公開する。単純な静的ホスティングだけではアカウント保存APIは動作しない。

`npm run dev`は画面開発用のViteサーバー。アカウントを含む統合動作には上記Worker・D1・ログイン情報を提供する環境が必要。カメラはHTTPSまたはlocalhostが必要。

## 検証

`tests/account.test.js`はSQLiteを使ってアカウント分離、認証必須、他オリジン拒否、重複加算防止、ベスト更新、購入残高と所有確認を検証する。`tests/auto-calibration.test.js`は自動姿勢合わせの条件を検証する。実際の姿勢認識精度は体格・部屋・カメラ位置に依存するため実機で調整する。

開発期間の目安は1か月。複数人プレイ、音声操作、ランキングは初期版の対象外。

### カメラ操作の応答調整

新しいカメラフレームを約30回/秒まで認識し、左右移動・タックの入力平滑化を速めた。ジャンプは基準姿勢または直前450msの低い姿勢から腰と足の上昇を確認する。小さな跳び上がりにも対応し、足が上がらない立ち上がりは除外する。ジャンプ後は着地と450ms以上の間隔を確認して再受付する。

`tests/body-control.test.js`は小ジャンプ、しゃがみからのジャンプ、立ち上がりや微小な揺れの除外、着地後の再受付を検証する。滑走テストでは自動姿勢合わせ中の記録保持と自動再開も確認する。実カメラでの認識精度と遅延は未検証で、端末や照明に依存する。
